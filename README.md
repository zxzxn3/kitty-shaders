# kitty 自定义 shader

七个效果，随便挑。都没有跨帧状态（没人用 `persist`）；只有 `cloud-bg` 用了一个临时
纹理 `a` 做两趟（按行抽样），其余都是单趟、直接写在 backbuffer 上。

| pipeline | 做什么 | 额外需要的 kitty 选项 |
| --- | --- | --- |
| `ink-stroke` | 光标移动时留下一道柔和的白色笔触 | `cursor_trail`、`cursor_trail_start_threshold 1` |
| `star-hash` | 哈希星场背景：纯星点，密度/亮度可控，很便宜 | 无 |
| `star-nest` | 深空星野背景：分形的星云絮状结构（贵一些） | 无 |
| `cloud-bg` | 体积云背景（重 raymarcher，会持续申请帧） | 无 |
| `layout-fade` | 当前窗口里没聚焦的分屏，颜色往黑白去 | 无 |
| `window-fade` | 失去焦点的那个 OS 窗口，整窗颜色往黑白去 | 无 |
| `focus-pulse` | 窗口获得焦点时内容区边缘有一次很轻的呼吸 | 无 |

四个背景类效果（`star-hash` / `star-nest` / `cloud-bg` / `bg-drift`）**互斥，只能开一个**：
它们都靠「和背景色比较」来认背景，先跑的那个会把背景染色，后跑的那个就认不出来了。

## 效果互相独立，按需挑

它们各写各的 backbuffer 输出，不共享状态或资源；每条管线的最后一组都写回
backbuffer，满足 kitty 对「最后一条管线最后一组」的要求。所以：

* 任意子集、任意顺序都能加载——把不想要的名字从 `custom_shaders` 里去掉即可
* 每条管线单独也能加载（只留 `focus-pulse` 也行）
* 组数是相加：1 + 1 + 2 + 1 + 1 + 1 = 7（上限 16）

这不是推断：早期四个效果时 **15 种组合**（4 个单条 + 6 个两两 + 4 个三三 + 1 个全部）
全部编译验证过；加 `cloud-bg` 之后是**六条管线合并**（7 个组）编译验证过。

`layout-fade` 和 `window-fade` 是两个独立管线，但共用同一个 shader 文件
`fade.slang`，靠组内变量 `WHOLE_WINDOW` 区分行为——kitty 按「组 + shader」分别编译，
所以那是两份独立特化，不是运行时分支。

## 参数放在哪

**每个效果的旋钮都写在它自己的 `.pipeline` 里**，用 `var` 覆盖 shader 的默认值。

有一条必须遵守的规则：**写在组内（group-level），不要写在管线顶层**。管线级 `var`
是全局按名字正则替换的，两个效果如果用了同名常量，后一条管线的值会静默覆盖前一条。
`layout-fade` 和 `window-fade` 共用 `fade.slang`、常量名完全相同（`FADE_*`），所以
两边的值都必须写在各自的组里，否则会互相覆盖。

其余效果的参数名也按效果加了前缀（`INK_` / `PULSE_`），理由相同。

## 启用

`~/.config/kitty/kitty.conf`：

```conf
custom_shaders ink-stroke star-nest layout-fade window-fade focus-pulse
# 笔触的坐标只能从拖尾几何里拿。默认阈值 2 会更晚起拖尾，打字时笔触更少。
cursor_trail_start_threshold 1
```

多条 pipeline 按声明顺序串联执行。

## 改完怎么生效

kitty 重载配置时会重新编译 shader，不用重启。但注意：**`auto_reload_config` 只监听
配置文件本身，不监听 `shaders/` 目录**——只改 shader 文件不会自动生效。所以
`kitty.conf` 里放了一个 `shader-rev` 计数，改 shader 时顺手把它 +1，自动重载就会
被触发。也可以手动：`kill -SIGUSR1 $KITTY_PID`，或者按 `ctrl+shift+f5`。

（顺带一提：每次重载 kitty 都会重新跑一遍 `slangc`，实测量级约 1 秒，和效果数量
关系不大——固定的几步占据了大部分时间。）

## ink-stroke —— 白色笔触

光标移动时留下一道柔和的白色笔触，只压在背景像素上，字一个像素都不碰。

单组、事件驱动、无状态：从 `cursor-trail-move` 到 `cursor-trail-stop`，每帧按当前
的拖尾几何（上一笔中心 → 这一笔中心）画一道软边笔尖。淡出交给 kitty 自己的拖尾
衰减，所以这里没有任何时间参数。

### 两处已知的取舍

* **墨不会留在屏幕上。** 淡出速度由 `cursor_trail_decay` 决定（默认 0.1–0.4 秒）。
  想让笔触留久一点就调它，例如 `cursor_trail_decay 0.3 0.8`——那是 kitty 原生
  选项，不是 shader 代码。
* **起笔是立即的，没有渐入**，而且光标只移动一格时可能不起拖尾
  （`cursor_trail_start_threshold` 的比较用的是 `<=`，所以阈值 1 实际要求移动 2 格；
  打字时连续几笔会累积到这个距离，所以第一笔可能没有笔触）。自带的那几个拖尾
  shader 也是这个行为。

### 可调参数

都在 `ink-stroke.pipeline` 的组内：

| 参数 | 作用 |
| --- | --- |
| `INK_STRENGTH` | 最浓时往墨色混多少，0.12 约等于原来墨痕刚落笔时那一档 |
| `INK_COLOR` | 墨色，默认纯白；写法 `float3(r, g, b)` |

笔尖半径、软边比例、背景容差是 `ink-stroke.slang` 里的实现细节，一般不用动。

## cloud-bg —— 体积云背景

移植自 nimitz 的 ["Protean clouds"](https://www.shadertoy.com/view/3l23Rh)
（`3l23Rh`；用户给的 `ttySzz` 是它的一个改版，只多了 `timeScaling`）。许可
**CC BY-NC-SA 3.0**：署名、非商业、相同方式共享。

### 为什么它能搬

它是**全程序化单趟** raymarcher：没有 `iChannel`（不依赖噪声贴图）、没有 Buffer
多趟反馈、只有一个 `mainImage`。Shadertoy 上大多数效果做不到这一点——噪声贴图和
多缓冲在 kitty 里根本拿不到——所以它属于"能搬"的那一类。

### 移植时踩到的三个坑

1. **矩阵列主序 vs 行主序**：GLSL 的 `mat2(c,s,-s,c)` 和 `const mat3 m3 = mat3(...)`
   是列主序，Slang 是行主序，照抄字面顺序等于转置。我离线渲染过两种写法：**转置后
   明显是另一张云**，所以这里显式转成了行主序。
2. **`p*m3` 与 `p.xy*=rot(a)` 的乘法方向**：两者在 GLSL 里都等价于"矩阵左乘向量"，
   Slang 里必须显式 `mul(M, v)`，否则得到转置后的效果。
3. **可变的全局变量**：原版用全局 `prm1` / `bsMo` 在 `mainImage` 里算、在 `map()`
   里读；这里改成参数传入，不依赖全局可变状态。

### 观感：默认是"淡"的

原图亮度（`CLOUD_STRENGTH = 1.0`）我用 CPU 复算过，平均亮度约 **0.45** 线性，
白字基本读不出来。所以默认给 **0.12**：平均 0.045、峰值 0.11，是很淡的一层。
想更接近 Shadertoy 原图就往上加，代价是文字对比度。

### 省电的三个杠杆

| 杠杆 | 位置 | 说明 |
| --- | --- | --- |
| 帧率 | pipeline 的 `animation_step 200` | 5fps；400 → 2.5fps，100 → 10fps |
| 步进数 | `CLOUD_STEPS`（默认 48） | 实测 48 与原版 130 几乎看不出差别；低于 32 会明显看穿 |
| 只在聚焦时动画 | 给这组加 `animation_start/stop` | 失焦完全不要帧；代价是切回来时云的相位跳一下 |

### 和 star-nest / bg-drift 是替代关系

三者**只能开一个**：都靠"和背景色比较"来认背景，先跑的那个会把背景染色，后跑的
那个就认不出来了。`bg-drift` 是轻量版，`cloud-bg` 是重度版，`star-nest` 是静态版。

## star-hash —— 哈希星场背景

不做分形、不做光线步进，就是"格子哈希撒星星"：像素坐标按 `STAR_CELL` 切格子，每个格子
用哈希决定这颗星存不存在、落在格子里哪一点、多亮、多大、偏冷还是偏暖，然后只算 3×3
邻域（星点半径远小于格子边长），按距离衰减成一个小圆点。哈希用的是 Dave Hoskins 的
"Hash without Sine"（MIT）。

### 比 star-nest 强在哪

| | 好处 |
| --- | --- |
| 密度/亮度/大小直接控制 | 不随窗口形状、视线方向漂移——star-nest 的黑电平是绝对阈值，改窗口形状浓度会差一倍 |
| 星点半径上限 2~3 像素 | 天然没有"大光斑"，也不需要亮度上限来救 |
| 每像素 9 次哈希、无循环无开方 | 比 star-nest 便宜两个数量级，所以帧率能给到 60fps |
| 漂移是真平移 | 看着是星星缓缓滑过，不是分形那种逐像素"沸腾" |

### 比 star-nest 弱在哪

**没有大尺度的星云絮状结构**。这里只用一个低频正弦叠出来的"银河带"（`STAR_BAND`）让疏密
有个大致的走向，不至于均匀得像噪点，但它毕竟不是分形，缺了那种"深空"的质感。

### 可调参数（都在 `star-hash.pipeline` 的组内）

| 参数 | 作用 |
| --- | --- |
| `STAR_CELL` | 格子边长（设备像素）。22 约等于 1/15 屏宽一格；越小星越密 |
| `STAR_DENSITY` | 有多大比例的格子有星（0.35 = 三成） |
| `STAR_BRIGHT` | 最亮的星亮度，线性，直接叠在背景上 |
| `STAR_SPEED` | 漂移速度（像素/秒），`0.0` = 完全静止（那就把 `animation_step` 也设 0） |

星点半径、冷暖白比例、银河带强弱收在 shader 里当常量。

## star-nest —— 深空星野背景

移植自 Pablo Roman Andrioli 的 "Star Nest"（Shadertoy）。用户给的 `shader1.txt` /
`shader2.txt` 是它的两个改版：一个让 `zoom` 跟着时间呼吸、视角跟鼠标，一个是固定
视角；本体（那两重循环）完全一样。这里按原作思路重写了一版，署名与许可以原作为准。

**能搬的理由和 cloud-bg 一样**：全程序化单趟，没有 `iChannel`（不依赖噪声贴图）、
没有 Buffer 反馈、只有一个 `mainImage`。

### 只有三个旋钮，其余全是常量

原作直接跑出来是「糊满整屏的褐色雾 + 一堆爆白的光斑」——那是 `v += fade` 那层底噪和
`a³` 的无上界累积造成的。为了"黑背景 + 不要大光斑"，只动了两处（都在 shader 里）：

| 旋钮 | 干什么 | 默认 |
| --- | --- | --- |
| `NEB_BLACK` | 黑电平：`a³` 先减掉 `NEB_BLACK³`，低于它的像素纯黑 | 18.0 |
| `NEB_BRIGHT` | 星云/星点亮度（原作 0.0015） | 0.0004 |
| `NEB_SPEED` | 漂移速度，`0.0` = 完全静止 | 0.0025 |

分形值 `a` 的分布（以 17 次迭代为单位）大致是：中位数 14.6、p90 ≈ 21、p99 ≈ 30。
所以 `NEB_BLACK = 12` 就接近原作那种浓度，18（当前）砍掉约七成像素、黑背景主导，
20 基本只剩星点。

**其余全部收进 shader 当常量的东西**：迭代/步进数（性能）、底噪 `NEB_HAZE`（原作 1.0，
这里 0.02）、饱和度（原作 0.85）、视场（原作 0.8）、亮度上限 `NEB_PEAK`（0.35，指数
软压缩——硬钳会在最亮那几团上压出一块实心白斑）。要动就直接改 `star-nest.slang` 顶部。

移植遗留也删掉了：原版从鼠标取的两个相机倾角、以及围着它们转的 `rot2` 辅助函数。
鼠标关掉后那两个角度就是常数，旋转不旋转只是换一片随机等价的星空。**唯一保留的移植
坑是 `glsl_mod`**：GLSL 的 `mod` 是 floor 语义、Slang 的 `fmod` 是截断语义，而这里坐标
有负值，照抄会得到另一片天。

### 一个已知的不稳定处

黑电平是**绝对阈值**，而分形场的统计随「视线方向 + 窗口长宽比」变化：同一份参数，竖屏
长窗口和横屏窗口出来的浓度能差一倍（CPU 复算：中位亮度 0.0074 vs 0.0039）。也就是说
你改窗口形状时，星的密度会跟着变。想更稳就只有换成下面那种哈希星场，它的密度和亮度
都是直接控制的。

### 性能

原作每个像素 20 步 × 17 次迭代 × 2 次 `length` = 680 次开方；这里 16 × 14 × 1
（同一个 `length` 复用给 `a` 和 `pa`，和原作等价）= 224 次，约 **1/3**。

迭代数现在是常量（14），累加出来的 `a` 与迭代数近似成正比，所以 shader 里乘一个常量
`NEB_ANORM = 17/14` 换算回原作 17 次的刻度，这样黑电平不用跟着迭代数改。

### `animation_step` 必须是周期帧，不能是 0

星野的相位来自 `d.timestamp`（真实时间），而 `animation_step 0` 只让这一组在**别的原因
重绘时**顺带跑一遍。两者的组合会产生一个很怪的现象：背景"动没动"被重绘频率绑架——

* 在 Codex CLI 这种一直在重绘的 TUI 里，它看着很正常地在动
* 普通终端空闲、或者窗口失焦（不再重绘）时，它整个冻住
* 滚进回滚缓冲时冻住，每滚一格又跳一下（每次滚动都是一次重绘）

改成 `animation_step 400`（2.5fps）后，运动只跟时间走，跟打字/滚屏/焦点无关。
实测：失焦且空闲的窗口，4 秒前后有 84% 的像素在变（改之前是 0%）。

2.5fps 配 `NEB_SPEED = 0.0025`：每帧只走格距的 0.03%，单帧看不出跳，几分钟能看出在漂。
**想彻底静止**（零开销、完全不随时间变）就把 `NEB_SPEED` 设成 `0.0`——那种情况下
`animation_step 0` 也是对的，因为画面本来就与时间无关。

### 两处已知代价

* 星点是**逐像素**算出来的，分辨率越高越细：在 1.5 倍缩放的屏幕上大约一个设备像素
  一个点，看着像很细的星尘，而不是"大颗的星"。
* 和所有背景类效果一样，它认背景靠「和 `d.background` 比色」，所以必须排在
  `ink-stroke` 之后、两个 fade 之前。

## layout-fade / window-fade —— 不活跃的部分颜色变淡

两个维度，一个 shader（`fade.slang`），两组参数：

* **`window-fade`**：这个 OS 窗口失去焦点 → 整窗去饱和
* **`layout-fade`**：当前窗口里没聚焦的分屏 → 那些分屏去饱和（活动分屏照常）

两个组互斥，各自只在对应的状态下活跃，所以同时启用也永远只上色一次：

| pipeline | 触发 | 停止 |
| --- | --- | --- |
| `window-fade` | `os-window-focus-out` | `os-window-focus-in` |
| `layout-fade` | `os-window-focus-in` | `os-window-focus-out` |

两者都只用事件、不写时长。`animation_step 0` = 不申请周期性帧（kitty 内部把它转成
`MONOTONIC_T_MAX`），只在别的原因触发重绘时跟着走；焦点变化本身就会触发重绘，
所以效果立刻出现，空闲时零开销。

`window-fade` 那组把 `WHOLE_WINDOW` 覆盖成 `true`，于是完全不需要遮罩；`layout-fade`
那组用 `d.active_window_geometry` 判断像素在不在活动分屏里，边界是硬的——分屏之间
的空白区本来就是背景色，羽化在那里看不出差别，反而会把活动分屏最外面那 1 像素轻微
褪色。只有一个分屏时整屏都在活动窗口里，`layout-fade` 等于不生效。

### 可调参数（两组各写各的）

| 参数 | 作用 |
| --- | --- |
| `FADE_DESAT` | 去多少饱和，0.0 = 不动，1.0 = 彻底黑白。含义是保留 (1 - FADE_DESAT) 的色度。当前 0.45 |
| `FADE_DIM` | 亮度系数，1.0 = 完全不动亮度（当前）；想额外压暗就往下调 |

因为写在组内，两个维度可以分别调——比如让分屏淡得更狠、整窗淡得轻一点。

### 对白字完全无效

白色没有色相，去饱和算出来还是白色。所以只有当屏幕上真有彩色内容（`ls` 的颜色、
语法高亮、彩色提示符、图片）时才看得出来。如果你希望失去焦点的窗口看起来更"退后"
一点，把 `FADE_DIM` 设成 0.92 左右——那一档几乎察觉不到，但能让黑白内容也有反应。

### 一个已知边界

如果 kitty 启动时窗口本来就是失焦的，两个组都不会被触发（事件只在变化时发），
那个窗口会保持原色，直到你聚焦它再失焦一次。

## focus-pulse —— 获得焦点时边缘的呼吸

一个窗口获得焦点时，内容区（不含标签栏那一条）边缘浮起一条很淡的光带，约 700ms
起落一次。

单组、事件驱动、无状态：`animation_start os-window-focus-in` 配 `animation_stop 600`，
强度按「到边缘的像素距离」衰减成 `PULSE_BAND_PX` 宽的一条带，envelope 是
`(1 - p) * smoothstep(0, PULSE_ATTACK, p)`——平滑起手约 70ms，然后落下。

**判据为什么是 `os-window-focus-in`**：它只在「这个 OS 窗口获得键盘焦点」时触发，
而且触发在获得焦点的那个窗口上。所以脉动出现在新窗口——旧窗口收到的是
`os-window-focus-out`。（一开始用的是 `user-activity`，那是"这个窗口收到了键盘或
鼠标输入"，于是点别的窗口时脉动落在旧窗口、打字时又一路触发。判据用错，症状就是
这两条。）

`animation_step 16` 只在动画那 600ms 里要帧，其余时间这个组不活跃，所以开销为零。

kitty 在管线载入后的第一帧也会补发一次 `os-window-focus-in`，所以每次重载配置时
当前窗口也会脉动一下。当成"shader 已经重新加载"的信号挺好用的，不用管它。

### 可调参数

都在 `focus-pulse.pipeline` 的组内：

| 参数 | 作用 |
| --- | --- |
| `PULSE_PEAK` | 最亮时叠多少，0.05 线性约等于 sRGB 0.24 |
| `PULSE_BAND_PX` | 光带宽度，像素 |
| `PULSE_ATTACK` | 起手用掉整段动画的比例，0.12 ≈ 70ms |

它是在当前颜色上做加法（不动 alpha），所以在纯黑背景上就是一层很淡的灰。嫌它吵就
把 `PULSE_PEAK` 降到 0.02，或者直接从 `custom_shaders` 里去掉这个名字。

想让它也在切换分屏时脉动，把 pipeline 里那行改成
`animation_start os-window-focus-in | window-focus-in` 即可。
